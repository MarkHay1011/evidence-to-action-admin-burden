# AI Governance Checklist for Non-Technical Teams

Use this checklist before introducing AI into an operational workflow.

## Workflow

- Workflow name:
- Owner:
- Date:
- AI tool or automation involved:
- Reviewer:

## 1. Purpose

- [ ] The workflow purpose is clear.
- [ ] The AI task is specific.
- [ ] The expected output is defined.
- [ ] Success can be measured.
- [ ] There is a named accountable owner.

## 2. Data

- [ ] The data source is known.
- [ ] Sensitive data has been identified.
- [ ] Personal data handling has been checked.
- [ ] Confidential information handling has been checked.
- [ ] Data retention and sharing risks have been considered.

## 3. Human review

- [ ] A human review point exists.
- [ ] The reviewer knows what to check.
- [ ] The reviewer can see source material where needed.
- [ ] The reviewer can reject or correct the AI output.
- [ ] Final accountability remains with a person or accountable team.

## 4. Risk boundaries

AI should not make unchecked decisions about:

- [ ] Clinical, medical, or veterinary judgement.
- [ ] Legal or regulatory obligations.
- [ ] Finance, pricing, payments, or eligibility.
- [ ] Employment, disciplinary, or performance decisions.
- [ ] Safety-critical actions.
- [ ] Access to services or support.

## 5. Output quality

- [ ] The output can be checked.
- [ ] The output includes uncertainty where relevant.
- [ ] Source-backed claims are traceable.
- [ ] Users know when AI has assisted the output.
- [ ] Known failure modes have been documented.

## 6. Pilot controls

- [ ] The pilot is small enough to monitor.
- [ ] A stop condition is defined.
- [ ] Errors will be logged.
- [ ] User feedback will be captured.
- [ ] The workflow will be reviewed before scaling.

## Decision

- [ ] Approved for limited pilot.
- [ ] Approved after changes.
- [ ] Needs specialist review.
- [ ] Do not proceed.

Record decisions, concerns, and unresolved questions here.
